# Documentation

- In our documentation, when a resource field allows a maximum of only one item, we do not format that field as an array. Instead, we create a subsection specifically for this field. Within this new subsection, we enumerate all the attributes of the field. Let's illustrate this with an example: [cloud_backup_schedule.md](https://github.com/mongodb/terraform-provider-mongodbatlas/blob/master/docs/resources/cloud_backup_schedule.md?plain=1#L207)
- You can check how the documentation is rendered on the Terraform Registry via [doc-preview](https://registry.terraform.io/tools/doc-preview).

## Creating Resource and Data source Documentation
We autogenerate the documentation of our provider resources and data sources via [tfplugindocs](https://github.com/hashicorp/terraform-plugin-docs).

### How to generate the documentation for a resource
- Make sure that the resource and data source schemas have defined the fields `MarkdownDescription` and `Description`.
  - We recommend to use [Auto-Generating Resources & Data Sources](development-best-practices.md#auto-generating-resources--data-sources-internal-tool) to autogenerate the schema via the Open API specification.
- Add the resource/data source templates to the [templates](https://github.com/mongodb/terraform-provider-mongodbatlas/blob/master/templates) folder. See [README.md](https://github.com/mongodb/terraform-provider-mongodbatlas/blob/master/templates/README.md) for more info.
- Run the Makefile command `generate-doc`
```bash
make generate-doc resource_name=search_deployment
```

## Reviewing documentation changes (Docs Cloud Team)

This section is for the Docs Cloud Team reviewers requested on a pull request. Whether a PR requests your review is decided by [`.github/CODEOWNERS`](https://github.com/mongodb/terraform-provider-mongodbatlas/blob/master/.github/CODEOWNERS); this section explains which changed files you are expected to review and what to check in them.

In short:

- Your files are `docs/` and `.changelog/`. Templates in `templates/` are shared with APIx-Integrations.
- Review wording, formatting, link style, and the user-facing accuracy of the description. The author is responsible for the technical correctness of the implementation.
- Autogenerated docs are not yours. Their text comes from the API definition, so send feedback to the API owner instead of editing the generated file.

### Which files are yours

| Changed file | Review? | What to check |
| --- | --- | --- |
| `.changelog/*.txt` | Yes | User-facing wording, the `release-note:{header}` type, the subcategory prefix (`resource/mongodbatlas_...`), and the framing of breaking changes. See the [changelog process](changelog-process.md). |
| `docs/resources/`, `docs/data-sources/`, `docs/ephemeral-resources/` (hand-written) | Yes | Descriptions and argument/attribute prose, example usage, the conventions on this page (for example, single-item fields are not formatted as arrays), and Registry rendering. |
| `docs/guides/*.md` | Yes | Migration and upgrade steps, version references, and links. |
| `docs/index.md` | Yes | Provider overview and navigation. |
| `templates/**/*.md.tmpl` | Yes, shared with APIx-Integrations | Template prose and structure. The generated files under `docs/` follow from these templates. |
| Autogenerated docs (the files listed in the generated block of `.github/CODEOWNERS`, which includes `*_api.md` and `*_api_v*.md`) | No | Owned by APIx-Integrations and generated from the API definition. Feedback belongs with the API owner, not the generated file. |
| `examples/**` | Not requested | Owned by the author and APIx-Integrations. If an example is wrong, comment on the PR. |
| `CHANGELOG.md` | No | Generated from `.changelog/`. Review the source entries instead. |
| Code, `tools/`, `.github/`, `scripts/` | No | Not documentation. |

### What to check by document type

- **Changelog entry**: clear user-facing wording, the correct `release-note` header, the right `resource/mongodbatlas_...`, `data-source/mongodbatlas_...`, or `ephemeral/mongodbatlas_...` prefix, and accurate framing for breaking changes. The format and the 24-hour review window are described in the [changelog process](changelog-process.md).
- **Resource and data source docs**: descriptions and argument prose, example usage, and the conventions listed at the top of this page.
- **Guides**: migration and upgrade steps are accurate, version references are correct, and links resolve.
- **Templates**: the same prose standards as the documents they generate.

### How to recognize autogenerated docs

- The generated block at the end of [`.github/CODEOWNERS`](https://github.com/mongodb/terraform-provider-mongodbatlas/blob/master/.github/CODEOWNERS) is the source of truth. It lists every autogenerated doc, including production resources whose names have no suffix, such as `log_integration`.
- Their implementations live under [`internal/serviceapi/`](https://github.com/mongodb/terraform-provider-mongodbatlas/tree/master/internal/serviceapi), so a PR that changes one of those packages corresponds to autogenerated docs. A few resources have hand-written docs despite a `serviceapi` implementation, so the CODEOWNERS block still decides.
- The `_api` and `_api_v*` suffixes only mark internal or pre-GA resources generated with the generic template, so those docs have no examples or import sections.
- Production autogenerated resources keep their regular names and can have a dedicated template, examples, and an import section, so do not rely on the name alone. Use the block.
- The block is kept in sync with [`tools/codegen/config.yml`](https://github.com/mongodb/terraform-provider-mongodbatlas/blob/master/tools/codegen/config.yml) by `make update-autogen-docs-owners`.

### What is already automated

- The [Docs Link Check](https://github.com/mongodb/terraform-provider-mongodbatlas/blob/master/.github/workflows/docs-link-check.yml) workflow checks relative links, anchors, and canonical `www.mongodb.com/docs` links on every pull request.
- Documentation is generated from templates and schemas, so the formatting of the generated content is not a manual review item.

### Where to send feedback

- Autogenerated docs: comment on the PR for the API owner. The text is generated from the API definition, so the fix belongs in the API, not the generated file.
- Implementation or API behavior: comment on the PR for the author.

Ownership on this page is derived from `.github/CODEOWNERS`, which is generated from `tools/codegen/config.yml`. Do not add a separate list of resources here; update the configuration and regenerate instead.
