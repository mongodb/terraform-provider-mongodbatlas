# Documentation

- In our documentation, when a resource field allows a maximum of only one item, we do not format that field as an array. Instead, we create a subsection specifically for this field. Within this new subsection, we enumerate all the attributes of the field. Let's illustrate this with an example: [cloud_backup_schedule.md](https://github.com/mongodb/terraform-provider-mongodbatlas/blob/master/docs/resources/cloud_backup_schedule.md?plain=1#L207)
- You can check how the documentation is rendered on the Terraform Registry via [doc-preview](https://registry.terraform.io/tools/doc-preview).

## Creating Resource and Data source Documentation
We autogenerate the documentation of our provider resources and data sources via [tfplugindocs](https://github.com/hashicorp/terraform-plugin-docs).

### How to generate the documentation for a resource
- Make sure that the resource and data source schemas have defined the fields `MarkdownDescription` and `Description`.
  - We recommend to use [Auto-Generating Resources & Data Sources](development-best-practices.md#auto-generating-resources--data-sources-internal-tool) to autogenerate the schema via the Open API specification.
- Add the resource/data source templates to the [templates](https://github.com/mongodb/terraform-provider-mongodbatlas/blob/master/templates) folder. See [README.md](https://github.com/mongodb/terraform-provider-mongodbatlas/blob/master/templates/README.md) for more info.
- Run the Makefile command `generate-doc`
```bash
make generate-doc resource_name=search_deployment
```

## Reviewing documentation changes (Docs Cloud Team)

This section is for the Docs Cloud Team reviewers requested on a pull request. Whether a PR requests your review is decided by [`.github/CODEOWNERS`](https://github.com/mongodb/terraform-provider-mongodbatlas/blob/master/.github/CODEOWNERS); this section explains which changed files you are expected to review and what to check in them.

### Which files to review

1. **Always review `.changelog/*.txt` entries.**
2. **For a changed resource, data source, or ephemeral resource doc**, check whether it has a template in `templates/resources/`, `templates/data-sources/`, or `templates/ephemeral-resources/` with the same name (for example, `docs/resources/log_integration.md` and `templates/resources/log_integration.md.tmpl`):
   - **A template exists**: review **only the template**, not the file under `docs/`. The file under `docs/` is generated from the template, the example files the template includes, and the attribute descriptions in the schema. Reviewing only the template avoids reviewing generated attribute descriptions by accident.
   - **No template exists**: review the file under `docs/`, unless it is listed in the autogenerated block of `.github/CODEOWNERS` (this includes every `*_api.md` and `*_api_v*.md` doc). Those are generated and are not yours to review. Otherwise the file is edited by hand, so suggest changes to it directly.
3. **Review `docs/guides/*.md`, `docs/index.md`, and `examples/**/README.md`.** They are edited by hand. Changes to `examples/**/README.md` do not request your review automatically, so review them when they are part of a PR you are requested on.

Everything else is not yours to review: `CHANGELOG.md` (generated from `.changelog/`), `docs/` files that have a template, the generic templates (`templates/resources.md.tmpl`, `templates/data-source.md.tmpl`), `templates/releases/`, code, `tools/`, `.github/`, and `scripts/`. Autogenerated docs without a template (including every `*_api.md` and `*_api_v*.md` doc) are not yours to review, even when they change in a PR you are requested on.

### What to check

- **Changelog entry**: clear user-facing wording, the correct `release-note` header, the right `resource/mongodbatlas_...`, `data-source/mongodbatlas_...`, `ephemeral/mongodbatlas_...`, or `provider` prefix, and accurate framing for breaking changes. The format and the 24-hour review window are described in the [changelog process](changelog-process.md).
- **Template or hand-edited resource, data source, or ephemeral resource doc**: overview and argument prose, example usage, the conventions listed at the top of this page (for example, single-item fields are not formatted as arrays), and Registry rendering. You review wording, formatting, and link style; the author is responsible for the technical correctness of the implementation.
- **Guides**: migration and upgrade steps are accurate, version references are correct, and links resolve.
- **Example READMEs**: clear instructions and accurate prerequisites.

### Where to send feedback

- **Template or hand-edited doc**: comment on the changed line. The author applies the fix.
- **Example code shown in a templated doc**: templates include example code from `examples/` (for example, `{{ tffile "examples/mongodbatlas_api_key/main.tf" }}`), so the fix is made in that file. Comment on the PR.
- **Attribute descriptions of autogenerated docs**: they come from the API definition, so the fix must be requested from the API owner. The template prose and examples of an autogenerated doc are still fixed in this repository.
- **Implementation or API behavior**: comment on the PR for the author.

### How to recognize autogenerated docs

- The generated block at the end of [`.github/CODEOWNERS`](https://github.com/mongodb/terraform-provider-mongodbatlas/blob/master/.github/CODEOWNERS) is the source of truth. It lists every autogenerated doc, including production resources whose names have no suffix, such as `log_integration`.
- The `_api` and `_api_v*` suffixes only mark internal or pre-GA resources generated with the generic template, so those docs have no examples or import sections.
- Production autogenerated resources keep their regular names and can have a dedicated template, examples, and an import section, so do not rely on the name alone. Use the block.
- The block is kept in sync with [`tools/codegen/config.yml`](https://github.com/mongodb/terraform-provider-mongodbatlas/blob/master/tools/codegen/config.yml) by `make update-autogen-docs-owners`. The rules above the block are maintained by hand.

### What is already automated

- The [Docs Link Check](https://github.com/mongodb/terraform-provider-mongodbatlas/blob/master/.github/workflows/docs-link-check.yml) workflow checks relative links, anchors, and canonical `www.mongodb.com/docs` links on every pull request, and checks external links in the changed Markdown files.
- CI fails if a `docs/` file that has a template does not match its sources, so generated docs cannot drift from their templates.
- The structure that tfplugindocs generates (headings and the schema attribute lists) is not a manual review item.
